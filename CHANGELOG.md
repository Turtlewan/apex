## [Unreleased]

### Added
- Planning intake v5 (2026-10-14, planning-intake-v5, apex-plan 2.9.0, apex-debug 1.5.0, apex-orchestrate 2.7.0): size/risk Intake routes Trivial, Normal and Big work (system maps, Big slices through the C1 planning gate and slice review); bug fixes hand the confirmed root cause back to Intake; a C4 plan pointer drives wave resume; an active Big plan stops on a label rise or contract change until owner re-approval.
- Bug Fix mode reference cleanup (2026-10-14, bugfix-mode-refs, apex-plan reference, session-context hook): remove the retired mode from the Checker routing row and ADR/status procedures while retaining Light rules.
- Scribe map update v2 (2026-10-14, scribe-map-update-v2, apex-code 2.27.0): a separate attended map dispatch updates affected system-map sections from the full build delta, receives its own Critic and family gates, and passes cover repairs and skipped sections to the technical-docs handoff.
- Critic plan-slice inputs (2026-10-14, critic-plan-inputs, apex-code 2.26.0, apex-critic agent): optional bounded plan-slice inputs (plan path as reference only, slice section, cross-slice contracts, cited map sections) for the Critic in spec mode, in code mode via the normal apex-code dispatch, and in the AFK whole-build pass, triggered by the spec's `plan: … · slice: …` Intent line; gate findings and other plan narrative stay excluded.
- Planning gate check (2026-10-14, planning-gate-check, apex-plan reference): Big changes get a gpt-6.1-sol xhigh planning-gate read in place of the pre-draft architecture pass, with digest-bound `gate-N` rows kept in a `docs/plans/<plan>.md` plan artifact (per-slice sections, wave column, In-Flight pointer, archive to `docs/plans/done/`); each eligible slice keeps an independent post-readiness cold read; the session hook Checker row names the gate.
- Drain close-out plan (2026-10-13, drain-close-out, apex-code 2.25.0): read-only `apex-drain-close.ps1 -Plan <drain-id> [-Json]` checks a complete drain end to end (commit chain, Engine identities, spec digests, blob identity, family-gate run IDs) and prints the ordered per-repo, per-spec close-out plan without writing anything; the attended five-step close-out sequence now lives in `apex-code/references/drain-close-out.md`. Per-spec Scribe is deferred for drained specs (ADR-049 decision 9). Wave 3 of the unattended drain.
- System map core (2026-10-13, system-map-core, apex-plan scripts + reference, apex-init 1.8.0): `apex-map-check.ps1` reads a repo's system map and reports stale sections (`-Stale`), contract/seam hits (`-Touches`) and owning components (`-Owner`) from Git history without writing to the repo; `apex-size-guard.ps1` checks a staged Trivial commit against its predicted paths and the 1-file/10-line limit; `references/system-map.md` defines the map format and the Trivial test; new projects get a map stub. Stage 6 wave 1 of the role redesign.
- Unattended drain runner (2026-10-12, drain-runner, apex-code 2.24.0): new `apex-drain.ps1 -Project <abs>` builds a project's sorted WILL BUILD queue serially through the Engine on a local `codex/drain-<id>` branch per build repo (never master, never pushed), commits each spec path-scoped after the full verify fence and blob identity checks, parks and restores failed specs and skips their dependents, waits out quota for at most 300 minutes, and writes only `docs/drain/<id>.md`; `-Resume <id>` continues a stopped drain. One drain per state root and build repo through durable lock and owner records. Wave 2 of the unattended drain (ADR-049).

### Changed
- Engine acceptance timeout (2026-10-11, engine-accept-timeout): the Engine's per-check acceptance timeout is now `-AcceptTimeoutMin` (1–240, default 60) instead of a hard 10 minutes, stored in the run state and overridable on `-Resume`; the expiry message names the actual minutes.
- Engine linked worktree (2026-10-11, engine-linked-worktree): the Engine builds with `-Repo` set to a linked worktree of the manifest repo (same git common directory), and hand-off path safety checks the target worktree instead of the main one; prerequisite for the unattended drain runner.
- Drain queue sorter (2026-10-11, drain-plan): new read-only `apex-drain-plan.ps1 -Project <abs> [-Json]` sorts a project's `docs/changes/*.md` into WILL BUILD (dependency order, HOST/OWNER-work flag) and NEEDS YOU (fixed reason codes with the root blocker), mirroring the Engine planner, capacity probe and critical-file classifier; `-Json` output is ASCII-escaped. The spec template's `## Prerequisites` now has a strict grammar (backticked spec names or `none`; apex-orchestrate 2.6.0). Wave 1 of the unattended drain (ADR-049).
- Default coder and wrapper model (2026-10-09, coder-default-gpt61): the Engine default and the `codex` alias, and the `codex-dispatch.ps1` `-Model` default, are now `gpt-6.1-sol`, so the Sol cold read and Codex review follow it; `gpt-5.6-sol` remains an allowed explicit pin. Skill prose updated (apex-code 2.23.1, apex-init 1.7.4, apex-orchestrate 2.5.1, apex-plan 2.8.1, apex-skill-author 2.0.4).
- Engine wave commit refusal (2026-10-09, engine-accept-smoke): an integration index missing wave-manifest paths, with no extra paths, now reports `integration index is missing wave-manifest paths:` instead of the "paths outside wave manifest" message; extra-path refusals are unchanged. This build was the first live run of Engine acceptance checks.
- Engine acceptance gate (2026-10-08, apex-code 2.23.0, spec contract 1.2.0): specs can tag acceptance blocks `powershell apex-accept`; the Engine runs task-labelled checks after each passing wave fence (failures retry on the effort ladder with the check's output tail in the next prompt) and unlabelled checks once after the final commit (failures park). Untagged criteria print as `HOST checks:`. Complete runs accept `-Teardown -Discard -Reason` after a repair; teardown adopts dead ledger rows. The validator refuses unsafe or mislabelled tagged blocks, sharing a grammar corpus with the planner.
- Stage 5 engine cutover (2026-10-06): the Engine is the default attended build route; Engine-refused specs use an attended HOST manual recovery path; the HOST owns close-out (Critic, Scribe, family gate, docs) against the integrated tip. The `apex-build-orchestrator` agent and its protocol schema are retired.
- Spec drafts (create and every revise) are now written by gpt-6-sol through the wrapper's `-AuthorSpec`, replacing the previous `model: opus` drafting worker; the host never edits a draft; revisions are digest-bound; a trial-log row is recorded at each promotion. The cold read uses gpt-6.1-sol via the wrapper default and is an independent same-family read; the Claude apex-spec-reviewer remains the cross-family spec check.
- The build orchestrator's planning and fallback routing now keeps Opus on the build-orchestrator and high-risk-reviewer roles, with spec authoring moved to gpt-6-sol.
- Session hook routing table updated: host/orchestrator is Opus 5.5, spec author is gpt-6-sol, with an independent Sol cold read for cross-checking.

### Fixed
- Git launcher stdin in the Engine and drain runner (2026-10-13, launcher-stdin): `apex-engine.ps1` `Invoke-RunnerGitBytes` and `apex-drain.ps1` `Invoke-DrainGit` redirect the Git child's stdin and close it right after start, so a Git call made inside a PowerShell `Start-Job` host no longer hangs forever on the inherited remoting pipe; `engine-git-test.ps1` and `apex-drain-test.ps1 -Case core` each gain a bounded Start-Job regression case.
- Git path decoding in the dispatch gates (2026-10-12, git-path-decoding): `codex-scope-check.ps1` and `tree-pin.ps1` now read Git path lists as strict UTF-8 `-z` records through a PATH-resolved process launcher (`.cmd`/`.bat` shims via `cmd.exe /d /v:off /s /c`, refusing two or more `%`), use literal pathspecs and ordinal case-insensitive path identity, and keep whitespace-edged and non-ASCII names distinct, so non-ASCII, quoted, space, glob-character and invisible-character paths are scoped and fingerprinted correctly (closes the tree-pin blind spot for C-quoted paths). Printed path text is ASCII-escaped (`\uXXXX`); ASCII fingerprints are unchanged except for previously wrong glob lookups and space-named paths.
