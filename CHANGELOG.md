## [Unreleased]

### Changed
- Engine linked worktree (2026-10-11, engine-linked-worktree): the Engine builds with `-Repo` set to a linked worktree of the manifest repo (same git common directory), and hand-off path safety checks the target worktree instead of the main one; prerequisite for the unattended drain runner.
- Drain queue sorter (2026-10-11, drain-plan): new read-only `apex-drain-plan.ps1 -Project <abs> [-Json]` sorts a project's `docs/changes/*.md` into WILL BUILD (dependency order, HOST/OWNER-work flag) and NEEDS YOU (fixed reason codes with the root blocker), mirroring the Engine planner, capacity probe and critical-file classifier; `-Json` output is ASCII-escaped. The spec template's `## Prerequisites` now has a strict grammar (backticked spec names or `none`; apex-orchestrate 2.6.0). Wave 1 of the unattended drain (ADR-049).
- Default coder and wrapper model (2026-10-09, coder-default-gpt61): the Engine default and the `codex` alias, and the `codex-dispatch.ps1` `-Model` default, are now `gpt-6.1-sol`, so the Sol cold read and Codex review follow it; `gpt-5.6-sol` remains an allowed explicit pin. Skill prose updated (apex-code 2.23.1, apex-init 1.7.4, apex-orchestrate 2.5.1, apex-plan 2.8.1, apex-skill-author 2.0.4).
- Engine wave commit refusal (2026-10-09, engine-accept-smoke): an integration index missing wave-manifest paths, with no extra paths, now reports `integration index is missing wave-manifest paths:` instead of the "paths outside wave manifest" message; extra-path refusals are unchanged. This build was the first live run of Engine acceptance checks.
- Engine acceptance gate (2026-10-08, apex-code 2.23.0, spec contract 1.2.0): specs can tag acceptance blocks `powershell apex-accept`; the Engine runs task-labelled checks after each passing wave fence (failures retry on the effort ladder with the check's output tail in the next prompt) and unlabelled checks once after the final commit (failures park). Untagged criteria print as `HOST checks:`. Complete runs accept `-Teardown -Discard -Reason` after a repair; teardown adopts dead ledger rows. The validator refuses unsafe or mislabelled tagged blocks, sharing a grammar corpus with the planner.
- Stage 5 engine cutover (2026-10-06): the Engine is the default attended build route; Engine-refused specs use an attended HOST manual recovery path; the HOST owns close-out (Critic, Scribe, family gate, docs) against the integrated tip. The `apex-build-orchestrator` agent and its protocol schema are retired.
- Spec drafts (create and every revise) are now written by gpt-6-sol through the wrapper's `-AuthorSpec`, replacing the previous `model: opus` drafting worker; the host never edits a draft; revisions are digest-bound; a trial-log row is recorded at each promotion. The cold read uses gpt-6.1-sol via the wrapper default and is an independent same-family read; the Claude apex-spec-reviewer remains the cross-family spec check.
- The build orchestrator's planning and fallback routing now keeps Opus on the build-orchestrator and high-risk-reviewer roles, with spec authoring moved to gpt-6-sol.
- Session hook routing table updated: host/orchestrator is Opus 5.5, spec author is gpt-6-sol, with an independent Sol cold read for cross-checking.
