# Aider — absorption analysis for APEX

Donor system: **Aider** (terminal AI pair-programmer, git-first, OSS since 2023).
Research date: 2026-06-03. Sources: aider.chat/docs + Aider-AI/aider repo (repomap.py read directly).

---

## What it is (sourced)

Aider is a single-process, git-first terminal coding agent. The human runs one CLI; Aider
holds a chat loop where each turn: (1) assembles context = explicitly-added files (full) +
an automatic **repo-map** (ranked signatures of the rest of the repo) + optional read-only
files (CONVENTIONS.md); (2) asks the model to return edits in a structured **edit format**
(search/replace blocks etc.); (3) applies the edits to disk; (4) **auto-commits** with a
conventional-commit message generated by a weak model; (5) optionally **auto-lints** and
**auto-tests** the edited files, feeding any non-zero-exit error output back to the model to
self-correct. Optionally splits the turn into an **architect** model (reasons/proposes) plus a
cheaper **editor** model (turns the proposal into apply-able edits).

The single most engineered piece is the repo-map: a tree-sitter + PageRank context-selection
engine whose explicit job is to fit the *most-referenced* identifiers of a whole repo into a
**token budget** (default 1k). Verified against `aider/repomap.py` on `main`.

## Mechanism inventory

### 1. Repo-map (tree-sitter ranked context selection) — VERIFIED from source
- Tree-sitter parses each file into an AST; tags are extracted and classed `def` (definition)
  or `ref` (reference). Builds `defines[name]→{files}`, `references[name]→[files]`,
  `definitions[(file,name)]→Tag`.
- Builds a `networkx.MultiDiGraph`: nodes = files, edges = "referencing file → defining file"
  per shared identifier, weighted.
- Ranks with `nx.pagerank()` using **personalization**: chat files get `use_mul *= 50`;
  identifiers explicitly mentioned in chat `mul *= 10`; "interesting" snake/kebab/camel names
  ≥8 chars `mul *= 10`; private `_`-prefixed and over-defined names get `*= 0.1`.
- **Token-budget fit:** `get_ranked_tags_map_uncached()` **binary-searches** the number of
  ranked tags to render, converting to a tree view, accepting when rendered
  `num_tokens ≤ max_map_tokens` within 15% error (`pct_err < 0.15`).
- Defaults: `--map-tokens` = **1024**. When **no files are in the chat**, budget is multiplied
  by `map_mul_no_files = 8` (≈8k) — i.e. it expands to help cold-start exploration and shrinks
  once the model is "focused" on files.
- Caching: per-file tags cached in a `diskcache` keyed on mtime (`.aider.tags.vN` dir); whole
  map cached on `(chat_files, max_map_tokens)`. So the map is cheap to recompute per turn.

### 2. Architect / editor two-model split — VERIFIED
- `--architect`: main (architect) model proposes a solution in prose; a separate
  `--editor-model` with `--editor-edit-format` (recommended `editor-diff`/`editor-whole`)
  converts the proposal into apply-able edits. Rationale (docs): some models reason well but
  edit poorly (o1/o3); splitting lets each play to strength, and even same-model-twice can win
  by giving "two requests to solve the problem."

### 3. Edit formats — VERIFIED (+ leaderboard "percent-correct-format" metric)
- `whole` (return full file — simple, costly), `diff` (search/replace blocks, git-conflict-
  marker syntax), `diff-fenced` (filename inside fence; for Gemini), `udiff`/`udiff-simple`
  (simplified unified diff; built to curb GPT-4-Turbo "lazy `# ...rest unchanged`" elisions),
  `editor-diff`/`editor-whole` (stripped prompts for architect's editor stage), `patch`.
- Search/replace block syntax:
  ```
  path/to/file.py
  <<<<<<< SEARCH
  original exact lines
  =======
  replacement lines
  >>>>>>> REPLACE
  ```
- Aider auto-selects a per-model default format. The leaderboard tracks **"percent using
  correct edit format"** as a first-class reliability metric — weak models fall to 67–85%,
  strong ones hit ~99–100%. **DeepSeek-V3.2 (Chat) = 98.2% correct format on `diff`.**

### 4. Auto-commit (dedup target) — VERIFIED
- One git commit per AI change-set; commit message generated by `--weak-model` from the diff +
  chat, default Conventional Commits. Pre-existing dirty files are committed *first* with their
  own message to isolate AI changes. `(aider)` author attribution; `/undo` reverts last change.

### 5. Auto-lint / auto-test loop — VERIFIED
- After edits: `--auto-lint` (on by default) runs `--lint-cmd` on edited files; non-zero exit →
  error text fed back to model to fix. `--auto-test` + `--test-cmd` does the same for tests.
  Loops on failure. (Aider ships a built-in tree-sitter-based linter as the default.)

### 6. CONVENTIONS.md auto-load — VERIFIED
- A project conventions markdown loaded **read-only** via `--read CONVENTIONS.md` / `/read` or
  persistent `read: CONVENTIONS.md` in `.aider.conf.yml`. Read-only = won't be edited + gets
  prompt-cached. Docs stress keeping it short; demonstrated to change model output (httpx+types
  vs requests+none).

## Dedup vs APEX

| Aider mechanism | APEX status | Verdict |
|---|---|---|
| Auto-commit + weak-model conventional message | **Already have** — per-spec/session commit discipline, stage-by-name, draft+approve, record SHA, hard-block push-to-main | Dedup. APEX's gated/approved flow is *deliberately stricter*; Aider's auto-commit is more aggressive. Nothing to absorb except the "commit dirty files first to isolate AI changes" micro-trick. |
| Repo-map ranked context selection | **Novel gap** — APEX names exact files in specs (no auto ranking) | Absorb **selectively** (planning-side only — see candidate 1). |
| Architect/editor two-model split | **Partial** — APEX's Claude-plans / DeepSeek-codes *is* an architect/editor split across backends | Dedup at the macro level; one micro-lesson on edit-format binding (candidate 2). |
| Edit-format discipline (diff/whole/udiff) + per-model default | **Novel gap** — APEX has no explicit "how DeepSeek must return edits" contract; it relies on Claude Code's native apply | Absorb as a DeepSeek reliability note (candidate 2). |
| Auto-lint / auto-test feedback loop | **Already have** — apex-code Verification Recipe (write→check→read-error→fix→re-run) per stack; apex-testing TDD | Dedup. Aider's "lint edited files only + feed exit-code text back" is the same loop. No absorb. |
| CONVENTIONS.md read-only auto-load | **Partial** — APEX ships `impl.md` per skill (coding conventions) auto-loaded by apex-code at pre-flight; project CLAUDE.md is auto-loaded | Mostly dedup; one idea (candidate 3). |
| `/undo` last-change revert | **Partial** — git history exists; no one-shot "undo last AI change-set" affordance | Minor; not worth a candidate. |

## Top absorbable candidates

### 1. Repo-map as a *planning-mode exploration* tool (NOT a per-turn coder context)
- **Change in APEX:** Add an optional planning-side capability (a step in `apex-plan` or a small
  helper) that, when a spec author doesn't yet know which files to name, runs a tree-sitter +
  PageRank ranked map to *surface the most-referenced files/identifiers* for a feature area —
  purely to help the planner **author the `## Files to change` list faster and more correctly.**
  It feeds the spec, then is discarded. It does **not** get injected into DeepSeek's context
  (that would violate APEX's no-exploration coding philosophy).
- **Token-cost when used: Med.** A 1k–8k-token ranked map is loaded **once, in planning**, to
  pick files; it never rides along on every coding turn. Net effect is likely token-*saving*
  versus the planner manually grepping/reading many files to discover structure. The High-cost
  failure mode (whole-repo map dumped into the coder's context every turn) is explicitly avoided.
- **Lean:** Strong fit *only* as a planning aid. Aider needs the map every turn because it has
  no upstream planner; APEX already has the planner, so absorb the map as that planner's
  discovery instrument, not as runtime context. Don't let it leak into coding mode.

### 2. Edit-format reliability binding for the weak coder (DeepSeek)
- **Change in APEX:** Add to `apex-code`/`apex-coding-principles` impl a short, explicit
  "edit-application reliability" note: prefer search/replace-style exact-match edits over
  whole-file rewrites for DeepSeek, and treat a failed apply as a verification failure to retry
  — mirroring Aider's per-model default + "percent-correct-format" mindset. Cite the data point:
  **DeepSeek-V3.2 hits 98.2% correct `diff`-format application** — i.e. DeepSeek *is* reliable
  with disciplined diff edits, which de-risks AFK builds.
- **Token-cost when used: Low.** A few lines of guidance in an already-loaded impl.md; no
  runtime overhead.
- **Lean:** High-value, near-zero-cost. APEX leans on Claude Code's native edit apply, but the
  *principle* (constrain a weak model to exact-match edits; verify the apply) directly hardens
  DeepSeek AFK runs. Absorb as a principle, not a new format engine.

### 3. Read-only conventions caching discipline
- **Change in APEX:** Note in `apex-code` that the stable convention layer (project CLAUDE.md +
  the bound `impl.md`s) should be positioned as **read-only, cache-stable context** — loaded
  once, never edited mid-build — so prompt-caching keeps it cheap across a long AFK build.
- **Token-cost when used: Low.** Reorders/labels existing context for cache hits; saves tokens
  over a long session rather than adding them.
- **Lean:** Mild. APEX already auto-loads impl.md; the absorbable nuance is the *read-only +
  cache-stable* framing for cost. Minor optimisation, not structural.

## Token-cost watchlist

- **Repo-map injected into the coder every turn — HIGH (the one to avoid).** This is Aider's
  default behaviour and the reason it spends a budget every turn. For APEX it would be pure
  waste *and* contradict the no-exploration spec model. Absorb the map **only** as a
  one-shot planning discovery tool (candidate 1), never as coding-mode runtime context.
- **Map with no files in chat = budget ×8 (≈8k) — Med/High.** Aider's cold-start expansion. If
  APEX ever uses the map in planning, cap `--map-tokens` low and keep it a single discovery
  pass, not a loop.
- Candidates 2 and 3 are **Low** — guidance text + cache framing, no runtime token addition.

- PageRank via networkx MultiDiGraph; def/ref tag extraction; chat-file ×50, mention ×10,
  name-heuristic ×10, private ×0.1 personalization weights.
- Binary-search token-budget fit; `pct_err < 0.15`; `--map-tokens` default 1024;

- Architect/editor split flags and rationale; edit-format list + search/replace syntax;
  leaderboard "percent correct edit format" metric; DeepSeek-V3.2 Chat = 98.2% on diff.
- Auto-commit (weak-model conventional message, dirty-commit-first, `(aider)` attribution,
  `/undo`); auto-lint default-on + auto-test feed-back loop; CONVENTIONS.md read-only load via
  `--read` / `.aider.conf.yml read:`.

  live leaderboard (figure reported via the leaderboard fetch, not the raw CSV).
