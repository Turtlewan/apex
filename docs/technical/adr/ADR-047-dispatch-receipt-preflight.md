# ADR-047: The dispatch receipt — re-execute the property, don't re-read the claim

**Date:** 2026-08-10
**Status:** Accepted
**Related:** ADR-039/ADR-040 (baseline-green gate, pre-dispatch pre-flight + spec validator — this
extends that pre-flight with a second, spec-bound gate), ADR-041 (wrapper hardening: scope, cap,
tree pin), ADR-042 (achievable cross-family review), ADR-032/ADR-034 (Sol plan-check and the
digest-bound `.review.log` sidecar), ADR-046 (D1 orchestrator ownership)
**Evidence:** Artemis `docs/learnings.md` §56–72; Sol cross-family deliberation, run `3e2eeef2`,
bundle digest `b66c33f0` (verdict BLOCK, 7 findings, all accepted)

## Context

The Artemis build pipeline failed repeatedly, and the failures looked unrelated until they were laid
end to end. They are one failure wearing seven costumes.

- **Stale verdicts read as live** (§71). A review verdict is a claim recorded at a moment. The gate
  that consumed it checked that a verdict *existed*, not that it described the bytes about to be
  built. A spec edited after adjudication carried its own approval forward.
- **Anchor and oracle rot** (§67, §69, §72). Specs cite files and pin measured numbers. Between
  authoring and dispatch both drift — a cited file is edited, a measured count changes — and nothing
  re-measured at the point of use. The spec still *looked* correct; every citation in it was a
  fossil.
- **Amendment loops regenerating defect surface** (§63, §70). Each repair round grew the spec, and
  defect surface tracked spec length rather than change size. Ceremony (proof-of-red, pinned counts)
  applied uniformly made every round longer than the last.
- **Tree drift under a gate** (§66). The tree a gate inspected was not always the tree the coder
  got.
- **Same-family review satisfying a command-shaped gate** (§59) and **unreviewed dispatch
  instructions injecting defects** (§60). Both are the same shape again: a recorded artifact
  (a review row, a dispatch pack) treated as trustworthy because it exists, not because anything
  re-derived what it asserts.

The common root cause, and the reframe Sol's F1 finding forced: **the pipeline validates artifact
shape and recorded claims instead of re-executing the underlying properties at the point of use,
with provenance.** Every listed failure is a claim that was true when written and false when read,
with no mechanism able to notice the difference. Adding more checks of the same kind — more shape
validation, more required fields — cannot fix this, because each new check is another claim to go
stale.

APEX already has three instances of the correct pattern, which is why the gap is visible at all:
`tree-pin.ps1` VOIDs a read-only verdict when the tree moves under it, the `.review.log` sidecar
binds a review round to `git hash-object` of the draft, and the M2b pre-flight re-runs the baseline
recipe rather than trusting a recorded green. Each binds one input. None of them compose, and
nothing binds the *set*.

## Decision

**A spec may be dispatched for a build only with a current dispatch receipt.** The receipt is
generated by `spec-preflight -Generate` at **promotion** — while the `.review.log` sidecar still
exists, since the promotion workflow deletes it — and travels with the spec into `docs/changes/`.
It is invalidated the moment any bound input moves. `codex-dispatch.ps1` re-derives the bindings
itself (`-Verify`) at the launch boundary and refuses the dispatch if any of them changed. A spec
with no receipt is refused; `-SkipReceiptCheck` is the bootstrap path for legacy promoted specs.

The receipt binds:

1. **Spec digest** — `git hash-object` of the spec file at generation time.
2. **Cited-file fingerprint** — the blob hash of every repo-relative file the spec cites, hashed
   from the **worktree**, not from `HEAD`. Hashing a commit range was the tempting cheap version and
   it is wrong: uncommitted state is exactly the state the coder will read (Sol F3, accepted).
3. **Verdict currency** — the last row of the spec's `.review.log` sidecar must carry *this* spec
   digest and a terminal-positive disposition. A digest-current BLOCK still blocks; a
   digest-mismatched row is VOID and fails the gate closed rather than being skipped (Sol F3,
   accepted).
4. **Probe results** — load-bearing measured oracles are declared as runnable probe blocks and are
   **re-run** at receipt time, never copied forward as text. `exact` probes fail on any drift;
   `required-subset` probes fail when a required member has disappeared, which is the asymmetry that
   a naive equality check gets wrong in the unsafe direction (Sol F3, accepted).
5. **Builder model family** and **6. dispatch-pack digest** — recorded now, enforced later. F4
   (pre-commit cross-family review is required) and F6 (dispatch packs are reviewed surface and must
   be digest-bound) are accepted decisions; their enforcement points are the commit gate and the
   pack builder, not this pre-flight. Carrying the slots in the receipt from day one means the
   follow-up work wires an existing field instead of migrating a schema.

**Fail-closed with typed exits.** Every refusal path — stale digest, VOID row, current BLOCK, moved
cited file, failed probe, unparseable input — returns a distinct exit code. A gate that cannot tell
the operator *which binding moved* produces the retry-until-green behaviour it exists to prevent.

**Builds are gated; reads are not.** The wrapper has exactly two phases, `build` and `review`
(`-Phase` is refused otherwise). The receipt gates `-Phase build`. Review-phase dispatches are
read-only and include the plan-check *that produces the very verdict row the receipt will bind* —
gating them would be a deadlock by construction: no spec could ever earn its first row.
`-SkipReceiptCheck` is the bootstrap escape, mirroring `-SkipBaselineCheck`, recorded loudly and in
the ledger row.

**Ceremony is proportional (Sol F7, accepted).** Proof-of-red tests and pinned counts are required
only where the deliverable *is* a guard. This ADR's own spec applies the rule to itself: the receipt
checker's refusal paths are guards and get proven-red fixtures; its plumbing does not.

## Consequences

- Two artifacts that were previously read as text — the `.review.log` sidecar and any measured
  oracle in a spec — become machine-consumed. The sidecar's disposition vocabulary must therefore
  become closed and mechanical, and probe blocks need an authoring format in the spec template.
  Both are follow-up work (`receipt-authoring-contract`); until they land, the checker fails closed
  on an unrecognised disposition, which is the correct default and a visible one.
- Existing specs have no receipts. Migration of Artemis's ready specs is an owner decision, held
  open deliberately: a forced migration would rewrite nine specs against a contract whose authoring
  half is not yet shipped.
- Re-anchoring evidence lives in the receipt, a machine artifact, and never as spec-text growth.
  This is the direct countermeasure to §63/§70: the repair loop can no longer lengthen the spec to
  record what it re-checked.
- Serial cadence (author → plan-check → adjudicate → build → verify → cross-family review → commit)
  follows from the mechanism rather than from discipline: batch-authoring interdependent specs now
  invalidates receipts as a side effect of each other's builds, which is the intended pressure.

## Rejected alternatives

- **Extend `apex-spec-validate.ps1` instead of adding a script.** The validator is a *shape* checker
  and is deliberately pure — it reads one file and executes nothing. The receipt's whole content is
  re-execution against the filesystem and against a sidecar. Folding it in would make the
  cheap-and-always-run structural gate expensive, and would put the two concerns behind one exit
  code.
- **Bind at commit time instead of dispatch time.** By then the defective build exists. The cost of
  the failures in §56–72 is paid during the build, not at the commit.
- **A required-fields check on the sidecar.** This is the failure mode restated: a present, well-
  shaped, stale row is exactly what §71 describes.
