# Spec: tree-pin adopts the in-process directory digest + fingerprints ignored entries

**Identity:** Replace `tree-pin.ps1`'s per-file `git hash-object` directory fingerprint with the in-process metadata digest, enumerate ignored entries (minus a runtime-noise list active ONLY on the session-runtime tree), and version the pin format so pre-scheme pins fail closed.
→ why: see docs/technical/adr/ADR-044-round8-deferred-designs.md (D1).

**All paths below are relative to the build worktree root; the host supplies the worktree (an isolated copy). Verify commands run from that root.**

## Intent
- **Intent:** tree-pin's directory fingerprint must (a) not spawn O(files) git processes for collapsed directories and (b) cover ignored files EXCEPT session-runtime noise, so `~/.claude`'s blanket-`*` churn moves the pin without the host's own Bash writes VOIDing every review — but only when the pinned tree actually IS the runtime tree.
- **Invariants:** verifying a fully-collapsed dirty directory spawns O(1) git processes for that directory; ignored (`!!`) churn OUTSIDE the runtime-exclusion list changes the fingerprint; ignored churn UNDER a list entry does not — but only when the worktree root equals the runtime-exclusion root; on any other worktree there are NO exclusions; TRACKED and untracked-`??` entries are NEVER excluded whatever their path; a pin written under the old scheme fails closed (exit 69) with a re-pin message; single leaf files keep a content hash.
- **Non-goals:** no change to the scope-check script (READ-ONLY reference; one-direction cross-reference comment tree-pin → scope-check only); no shared helper module; no detection of a same-path+length+mtime-but-different-bytes directory rewrite, and no detection of empty-directory churn inside a collapsed ignored dir (enumeration is files-only) — both accepted deliberately to keep the mechanism identical to scope-check's; git C-quoted (Unicode) ignored paths retain trim-only handling (scope-check C-unquotes; tree-pin does not, by design) — a pre-existing individually-listed Unicode ignored path can digest as missing, an accepted per-script difference. Partial-collapse per-file hashing is a stated limit. All `harness-known-limits.md` rows for these are written by the HOST at wave close (this spec does NOT touch that file).

## Assumptions
- The scope-check in-process digest (`codex-scope-check.ps1`, ≈238-253) is the reference and its shape is current → impact: Stop (mirror must match).
- `tree-pin.ps1` line numbers (Get-PathDigest 93-117, enumeration 144, pin writer 181-190, digest reader 217, detail extraction 227) are approximately current → impact: Caution (locate by content, not line).
- `git status --porcelain --ignored` marks ignored rows with the `!!` XY code → impact: Stop (the exclusion keys off `!!`).
- The runtime-exclusion list matches the session-75 adjudication class → impact: Stop.
- The tree-pin test's exact-byte fixture (≈135-137) is regenerated by tasks → impact: Caution.

Simplicity check: yes — considered a shared digest helper; rejected because a missing helper is a new fail-open surface (ADR-044 D1). One-direction cross-reference comment instead.

## Build isolation
`tree-pin.ps1` is invoked by `codex-dispatch.ps1` during any dispatch to pin and verify the tree. The build runs in an ISOLATED WORKTREE copy (round-8 W3 pattern), NOT the live tree; the host integrates the diff and re-runs the suites on the live tree post-integration, with no gates open during integration. This closes the mid-wave self-mutation hazard — a v1/v2 pin-format transition landing between a sibling dispatch's pin and its verify.

## Tasks
- [ ] **Task 1:** In `skills/apex-code/scripts/tree-pin.ps1`, replace `Get-PathDigest`'s directory branch (≈93-117) with the in-process digest EXACTLY mirroring the scope-check digest (`codex-scope-check.ps1` ≈238-253, READ-ONLY — do NOT edit it): `Get-ChildItem -Recurse -File -Force` sorted by `FullName`; per file fold `relPath|Length|LastWriteTimeUtc.Ticks`; join `\n`, UTF-8, SHA-256; emit `dir:<hex>`, empty dir `dir:empty`, enumeration error folds `UNREADABLE|<count>`. Keep `git hash-object` for single leaf files. Add a one-direction cross-reference comment (tree-pin → scope-check). — files: skills/apex-code/scripts/tree-pin.ps1 — done when: a fully-collapsed directory fingerprint spawns no per-file `git hash-object`.
- [ ] **Task 2:** Change the enumeration (≈line 144) to `git status --porcelain --ignored=traditional` (matching scope-check `Get-DirtySet` ≈154). Add a parameter `-RuntimeExclusionRoot <path>` defaulting to `$env:USERPROFILE\.claude`. The runtime-exclusion filter activates ONLY when the resolved worktree root equals `-RuntimeExclusionRoot` (canonical path compare, case-insensitive); on any other worktree NO exclusions apply. When active, an entry is excluded IFF (its XY status is `!!`) AND (its repo-relative normalized path equals, or is a descendant of, a fixed repo-root-anchored list entry): `sessions/`, `projects/`, `backups/`, `jobs/`, `shell-snapshots/`, `todos/`, `file-history/`, `history.jsonl`, `.last-update-result.json`. EVERY entry matches equality-or-descendant uniformly (`history.jsonl` and `history.jsonl/child` both excluded). Tracked/`??` rows are NEVER excluded. — files: skills/apex-code/scripts/tree-pin.ps1 — done when: with the worktree root equal to `-RuntimeExclusionRoot`, ignored churn under a list entry is dropped and ignored churn outside it is not; with a different worktree root, no churn is dropped.
- [ ] **Task 3:** Version the pin format on BOTH sides. Writer (≈181-190): `-Pin` writes `treepin-v2` as the new first line. Readers shift: digest read (≈217) 0→1; detail extraction (≈227) `-Skip 1`→`-Skip 2`. `-Verify` on a pin whose first line is not `treepin-v2` exits 69 with the stdout message `pin predates digest scheme v2 — re-pin` (NOT the THE TREE MOVED banner). The re-pin text is tree-pin's own stdout; `codex-dispatch` and other consumers still treat exit 69 as tree_moved (fail-closed, unchanged). — files: skills/apex-code/scripts/tree-pin.ps1 — done when: a fresh `-Pin` then immediate `-Verify` on an unmodified tree exits 0; a v1-format pin verifies to exit 69 with the re-pin message.
- [ ] **Task 4:** Update `skills/apex-code/scripts/tree-pin-test.ps1`: regenerate the exact-byte fixture (≈135-137); preserve ALL existing locks (pin regex `^\[tree-pin\] pinned [0-9a-f]{12} for '<label>'$`, clean-verify unchanged-message regex, exit codes 0/69, pin-file naming `apex-treepin-<safeLabel>-<10hexTag>.txt`). Exclusion cases pass the scratch repo as `-RuntimeExclusionRoot`. ADD deterministic cases: (i) new ignored file NOT under an excluded dir → 69; (ii) new ignored file UNDER an excluded runtime dir → 0; (iii) pre-existing ignored dir unchanged → 0; (iv) v1-format pin → 69 re-pin; (v) fresh `-Pin` then `-Verify` unmodified → 0; (vi) v2-vs-v2 move renders ≥1 CHANGED/NEW/GONE detail line; (vii) TRACKED rename into an excluded dir still moves → 69; (viii) content mutation INSIDE a pre-existing collapsed non-excluded ignored dir → 69; (ix) churn to exact-file entry `history.jsonl` → excluded → 0; (x) near-miss `projectsX/` ignored file → 69; (xi) a `??` untracked file under an excluded prefix → 69 (only `!!` rows filtered); (xii) `nested/projects/` ignored file (worktree = runtime root) → NOT excluded → 69 (root anchoring); (xiii) a DIFFERENT worktree (its root ≠ `-RuntimeExclusionRoot`) with an ignored `projects/x` file → still moves → 69 (no exclusions off the runtime tree). — files: skills/apex-code/scripts/tree-pin-test.ps1 — done when: suite fully green including all added cases.
