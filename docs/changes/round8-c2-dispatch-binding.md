# Spec: dispatcher post-hoc critical classification (exit 77) + per-attempt tree-digest binding (exit 78)

**Identity:** Wire D6 into `codex-dispatch.ps1` through ONE shared post-hoc helper: record `head_sha` (warn on `-BaseSha` drift) and `end_tree_digest`; classify the coder's actual writes and fail closed on an unconfirmed CRITICAL write with a new exit 77 (subordinate to the existing precedence ladder); bind a review launch pin-first to its referenced build's tree digest with a new exit 78; carry both controls to the adopt path from recorded row state; and update `SKILL.md` (exit rows + the in-session row shape).
→ why: see docs/technical/adr/ADR-044-round8-deferred-designs.md (D6 items 1 + 5, and Grounding addendum 2026-07-18 reserving exits 77/78).

## Intent
- **Intent:** Move critical-file confirmation from grant-token heuristics to the coder's real writes, and give a review a verifiable, race-free identity beyond `run_id` — on the main path AND the adopt path — with every new external call funnelled through one fail-closed helper.
- **Invariants:** Post-hoc classification runs ONLY for a scope-armed `build`+`workspace-write` run; it is never an exit itself — it sets `critical_violation` and the existing precedence ladder decides the exit (blocked 67, tree-moved 69, bad-list 66, scope 65 all outrank the new 77 rung; a HEAD-move surfaces as a scope non-zero → exit 65 with `critical_violation:true` still recorded). A HARD-BLOCK (classifier exit 11) forces `critical_violation:true` regardless of confirmation; an exit-10 critical is `false` only with confirmation; a missing written-set file, a scope-check throw, or any classifier outcome ∉ {0,10,11} all fail closed to `true`. A `-ScopeUnlocked` build records `critical_violation` ABSENT (pre-flight `-CriticalFilesConfirmed` was already required). A review launch refuses (exit 78) when the referenced build row is not found (pre-reservation, no row), when the referenced digest is empty/whitespace/`unverifiable`, when the live digest is uncomputable, or when the digests differ (post-reservation, reserved row updated `failed`/`digest_mismatch:true`); it records `reviewed_tree_digest` (the PINNED tree's digest) on a match. Only a FOUND build row whose `end_tree_digest` PROPERTY is absent is migration-safe (WARN + proceed). A `-TreePinScript` override on a review carrying `-ReviewedRunId` records `tree_pin_override:true` so c3 refuses to let that row vouch. An uncomputable digest is recorded as the literal `unverifiable`, never empty. A `-BaseSha` mismatch WARNS, never refuses.
- **Non-goals:** No change to the pre-flight Layer-B critical gate (≈823-868, exit 76) — exit 77 is the post-hoc complement. No change to the family-gate compare beyond what round8-c3 consumes. No new digest/emitter code (consumed from round8-c1).
- **Accepted limits:** (mtime cross-time) the digest folds untracked/ignored files' mtimes (`tree-pin.ps1` ≈101-104) → a spurious exit 78 on an mtime-only touch; recovery is the attended human-review ledger row; no new override switch. (broad matchers) post-hoc classification inherits the classifier's broad matchers (lock / hooks / secret-substring / auth-stem); a false positive needs attended `-CriticalFilesConfirmed` or host adjudication. (scope-unlocked) a `-ScopeUnlocked` build has no written set — classification is unavailable and `critical_violation` is absent; pre-flight confirmation already gated it. (pre-completed adopt) an adopt that REUSES a recorded scope verdict has no written set — `critical_violation` absent + WARN.

## Specialist Context
### Security
One `Invoke-PostHocGates` helper funnels every new external call through try/catch + `$LASTEXITCODE` seeding + `^[0-9a-f]{64}$` validation, so the main and adopt paths cannot diverge into a fail-open. Classification is not an exit — it feeds `critical_violation` into the existing precedence ladder, so a blocked/tree-moved/scope failure keeps its own code while the field is still recorded; the 77 rung fires only when nothing higher applies, and a hard block (exit 11) is never confirmable. The review binding is pin-first: the pinned tree and the compared digest are the SAME `treepin-v2` fingerprint, so no writer can move the tree between compare and pin; the referenced-row lookup fails fast pre-reservation (no orphan row). A `-TreePinScript` override on a bound review is recorded as `tree_pin_override:true` and c3 refuses to let that row vouch — tests may inject freely because they assert exits, not vouching. Adopt uses the ROW's recorded `critical_files_confirmed`, never the adopt invocation's own switch — an unrecorded confirmation during adoption is forbidden. `-ScopeUnlocked` and pre-completed adopts have no written set → `critical_violation` absent, and pre-flight confirmation / host adjudication cover them.

### Performance
Digest reuses c1's in-process fingerprint (no `git hash-object` storm); the review binding reads the pin file `-Pin` already wrote (no second computation). The classifier runs twice per scope-armed dispatch (pre-flight ≈846 + post-hoc) — one extra spawn, accepted.
