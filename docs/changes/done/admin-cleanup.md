# Spec: Administrator cleanup of retained APEX artifacts
<!-- Governing contract: skills/apex-code/references/spec-contract.md. -->

**Identity:** One list-first administrator cleanup command for retained worktrees, recorded task branches, Engine history, and test scratch directories.

## Intent
Provide the owner with one supported command to inspect accumulated build artifacts, remove ordinary items proven safe against each main checkout's committed HEAD, and remove earlier quarantines only through the owner's per-path y/n channel.
For ordinary cleanup, preserve unique staged, working, untracked, and non-disposable ignored content; preserve items with live or unresolved users; repeat proofs inside the dispatch mutex immediately before mutation. For named quarantine removal, the owner's y supplies content authorization; retain the administrator, machine-wide guard and deletion-boundary requirements in Task 1.
Default listing changes nothing. The owner runs administrator Apply when no builds are running; ordinary Apply removes only eligible proven items; `-Apply -RemoveQuarantine <path>` performs only the named owner-authorized removals. Apply leaves append-only ledger records and Engine state contents unchanged, appends its own cleanup journal, and reports each decision. A build started after the final guard check and before a rename is not excluded: no shared cross-session lock exists, and adding one is out of scope; an Engine idling between coder launches inside a host launcher script whose command line names none of the matched scripts, with state under a StateRoot this invocation does not inventory, is also not detected; the owner runs Apply only when no builds are running and passes `-StateRoot` for any non-default state directory in use.
Keep Engine teardown behavior intact and amend the teardown doctrine and close-out wording to the owner-approved cleanup channel.
Non-goals: dispatcher or Engine behavior changes, new ledger rows, scheduling, the scope-temp leak source fix, and the separate spec 4b review fixes.
Split waiver: six build files implement one cleanup concern; two file-disjoint coder tasks share one wave with serial execution at High risk.
