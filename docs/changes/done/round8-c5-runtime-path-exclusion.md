# Spec: scope-check runtime-path exclusion — untracked session churn no longer arms exit 65

**Identity:** Teach `codex-scope-check.ps1`'s `-Check` attribution to EXCLUDE non-host-curated paths under the Claude session-runtime dir list (`sessions/`, `projects/`, `backups/`, `jobs/`, `shell-snapshots/`, `todos/`, `file-history/`, `history.jsonl`, `.last-update-result.json`) from coder attribution — from the violation set AND from the `-WrittenPathsFile` written set — but ONLY when the worktree IS the runtime root, and ONLY while the path is NOT host-curated (absent from BOTH the git index AND HEAD). A path present in the index OR in HEAD (a force-added memory/skill file, or a committed runtime file a coder deletes/renames — host-curated state) stays fully checked. This mechanizes the interim host adjudication of exit-65 dispatches whose flagged list was a subset of runtime dirs.
→ why: the live `~/.claude` tree co-hosts the session runtime; while a session runs, the host's own churn under those dirs lands in the `-Check` violation set (and, since c1, the `-WrittenPathsFile` written set), so every wrapper dispatch into that tree fails scope (surfaced as exit 65 at the dispatch layer) and had to be adjudicated by hand.

## Intent
- **Intent:** Discriminate host session-runtime churn from coder writes using git REFS (the INDEX or HEAD), per Sol's step-2.5 design note plus the host-approved widening (2026-07-19): the blanket `*` gitignore makes runtime churn ignored/untracked (`!!`), while force-added memory/skill files are TRACKED and committed runtime state lives in HEAD — so git-status CLASS is useless (churn is `!!`, not `??`) and ref-presence is the discriminator. Not-host-curated (in NEITHER index NOR HEAD) under a runtime dir = host churn → exclude; present in the index OR in HEAD = host-curated state → keep checking. The HEAD half is load-bearing: index-only would read a `git rm`'d or rename-SOURCE tracked runtime file as untracked and mask a coder deleting host-curated state — HEAD still holds it, so it stays checked.
- **Invariants:**
  - The exclusion lives in `-Check` ONLY (see the Snapshot-vs-Check determination below). `-Snapshot`, `-EncodingScan`, `-Pin`/`-Verify`/`-Digest` (tree-pin) are byte-identical to today.
  - The exclusion fires ONLY when the resolved worktree equals the resolved `RuntimeExclusionRoot` (default `$env:USERPROFILE\.claude`; overridable via a new `-RuntimeExclusionRoot` parameter for tests) — matching tree-pin.ps1's per-tree `$ApplyRuntimeExclusions` gate. Off the runtime root, behavior is unchanged.
  - The runtime dir list and its equals-or-prefix root-scoping MATCH tree-pin.ps1's `$runtimeExclusions` (tree-pin ≈159-169) and its match rule (tree-pin ≈179-189) exactly. The two lists are duplicated (no shared module — these are standalone `.ps1`), coupled by a sync comment on BOTH sides.
  - The discriminator is a DEDICATED new helper `Test-IsHostCurated $n`, NOT the existing `Get-IndexHash` (which other callers — `Get-PathState` at ≈289-291 — depend on unchanged). It is a pure SET-MEMBERSHIP lookup against two inventories loaded ONCE per `-Check` (only when `$applyRuntimeExclusions` is true), NOT a per-path git query: the checker measured 139 runtime tokens → 277 subprocesses → 11.6 s per `-Check` under the per-path design, so per-path calls are rejected. A path is host-curated iff it (or, for a collapsed directory token, any descendant of it) is present in EITHER the full INDEX inventory (one `git ls-files -z`) OR the full HEAD inventory (one `git ls-tree -r --name-only -z HEAD`). Both inventories are worktree-independent (they read refs, not the working file), so a GONE / deleted / renamed runtime path is classified correctly. Pure set membership means there is NO pathspec matching at all, so pathspec metacharacters (`projects/file[1].txt`) are a non-issue — no `--literal-pathspecs` machinery is needed. Deliberately UNLIKE tree-pin's `$xy -eq '!!'` status-class gate: a fixture untracked (`??`) runtime file with no blanket gitignore is still excluded (it is in neither inventory), and a `git rm` of a committed runtime file is still checked (the HEAD inventory holds it).
  - **Fail CLOSED, never open.** If either inventory call fails (guarded `Invoke-Git` throws), NO exclusions happen this run — every path stays fully checked, exactly as today off the runtime root — and a loud note says the runtime inventory could not be built so nothing was excluded. A gate that cannot enumerate host-curated state must not mask anything.
  - **Point-in-time inventories (accepted limit).** The two inventories are read ONCE per `-Check`, before the attribution loop begins — a point-in-time snapshot of host-curated state. The "present in the index OR HEAD stays checked" guarantee therefore holds AS OF that read: a runtime path staged into the index (or committed) AFTER the inventories are loaded, but before the loop visits it, can be excluded on that run. This is a narrow concurrent-mutation window that OVERLAPS the accepted brand-new-file limit (Non-goals) — a path not yet curated when the inventory is taken is treated exactly like session churn — and is accepted on the same terms, with the same three defenses (`--sandbox`, the review gate, the human diff).
  - Exclusion is applied per path at the TOP of the attribution loop (before authorized/violation classification), in BOTH the `$collectWritten` branches, over the FULL `$allPaths` union (snapshot-sourced AND now-dirty). An excluded path adds nothing to `$violations` and nothing to `$writtenSet`.
  - Exclusion is LOUD: after the loop, when the excluded count N>0, print one line `[scope] N runtime path(s) excluded (session churn under runtime dirs; index/HEAD-tracked paths still checked)` so a human reading the log sees the mask exists. Printed on every attribution-reaching outcome (clean, out-of-scope, mangled-allowlist).
- **Non-goals:**
  - No change to the SNAPSHOT phase (it keeps recording every dirty path, including runtime churn — required; see determination). No new exit codes. No dispatch-layer wiring (the exit-65 mapping lives in dispatch-preflight/dispatch and is unchanged; this fixes the violation SET it reads from).
  - No extraction of the runtime dir list into a shared module — the list is duplicated and coupled by comment, per the fixed design.
  - **ACCEPTED LIMIT (host-decided, UNCHANGED by the widening):** a brand-NEW file a coder drops under a runtime dir is masked — indistinguishable from host churn by construction (a new file is in NEITHER the index NOR HEAD, exactly like the session's own churn). The index-OR-HEAD widening only recovers deletes/renames of ALREADY-curated state; a genuinely new untracked coder file remains masked. Pattern-tightening was attempted in audit step 2.5 and pulled as too hard; accept-as-stated. The defenses that remain for that path are `--sandbox`, the review gate, and a human reading the diff — the same trio the scope check has always deferred to for a bad-faith coder.

## Assumptions
- The script has NO existing full-index parse to reuse — `Get-IndexHash` (≈279-287) queries one path at a time. So the two inventories are loaded fresh, once each, when `$applyRuntimeExclusions` is true: `git ls-files -z` (index) and `git ls-tree -r --name-only -z HEAD` (HEAD). `-z` (NUL-delimited) sidesteps git's C-quoting of unusual bytes, so no `Unquote-GitPath` step is needed; split the joined output on NUL (ignoring the trailing empty split entry), `Normalize` each entry, and load into two `System.Collections.Generic.HashSet[string]` built with `[System.StringComparer]::OrdinalIgnoreCase` (a StringComparer INSTANCE — NOT the `[System.StringComparison]` enum, which makes the `HashSet[string]::new(...)` constructor ambiguous and throws on Windows PowerShell 5.1; Windows paths are case-insensitive): a FILE set (every inventory path) and a DIR set (every ANCESTOR directory prefix of every inventory path — `projects/sub/keep.txt` contributes `projects` and `projects/sub`). `Test-IsHostCurated($n)` is then O(1): `$fileSet.Contains($n) -or $dirSet.Contains($n)`. A collapsed dir token (`?? projects/` → Normalized `projects`) with ANY curated descendant hits the DIR set → host-curated → NOT excluded (fail-safe over-checking); a leaf hits the FILE set only if itself curated; a fully-untracked, fully-un-HEAD'd dir is in neither → excluded. This is the intended fail-safe direction: uncertainty checks more, never less → impact: Stop
- `Invoke-Git` (≈111-145) runs `git -C $repo @GitArgs` and throws on launch/non-zero exit — used verbatim for both inventory calls. A VALID snapshot already requires an initial HEAD (the snapshot calls `Invoke-Git rev-parse HEAD` at ≈535 and throws on an unborn HEAD), so `-Check` normally has HEAD. But the phases are separate: if HEAD becomes unborn/unqueryable between snapshot and check, the `ls-tree HEAD` inventory call throws — which is caught and FAILS CLOSED (no exclusions this run, everything stays checked, loud note), never masks. Either inventory call throwing takes the same fail-closed path → impact: Stop
- `$repo = (Resolve-Path $Worktree).Path` is set at ≈97 (runs for every mode); the attribution loop's `$n` is already `Normalize`-d (`$allPaths` built via `Normalize` at ≈645-647) → the runtime match compares like-for-like against the (forward-slash, no-trailing-slash) dir list → impact: Stop
- The `-Check` attribution loop has TWO structurally-identical branches — `$collectWritten` true (≈651-703; `foreach` at ≈653) and false (≈704-738; `foreach` at ≈705) — each opening with `if (Test-IsAuthorized $n)` then `Test-IsStatePath`. Inserting the runtime gate immediately after each `foreach ($n in $allPaths) {` (≈653 / ≈705), BEFORE `Test-IsAuthorized`, excludes non-host-curated runtime paths unconditionally (the design's only carve-out is "unless host-curated", not "unless authorized") → impact: Stop
- The union `$allPaths` (≈645-647) already carries snapshot-sourced (preDirty) paths, so a runtime path dirty at snapshot then GONE now is visited by the loop and caught by the top-of-loop gate before the GONE classification (≈678 / ≈716) — no separate snapshot-side handling needed → impact: Stop
- The `-WrittenPathsFile` emission slot (≈740-760) expands ONLY entries already in `$writtenSet`; an excluded path never enters `$writtenSet`, so it is neither emitted nor directory-expanded → impact: Stop
- tree-pin.ps1 owns the canonical semantics to mirror: `-RuntimeExclusionRoot` default `(Join-Path $env:USERPROFILE '.claude')` (≈32), the 9-entry `$runtimeExclusions` list (≈159-169), the resolve-and-compare root gate (≈204-221), and the equals-or-`prefix + '/'` OrdinalIgnoreCase match (≈179-189). Copying these verbatim keeps the two gates coupled → impact: Stop
- Existing scope-check-test.ps1 fixtures live under `$env:TEMP` and pass no `-RuntimeExclusionRoot`, so their resolved worktree never equals the default runtime root → `$applyRuntimeExclusions` is false for every existing case → all 19 emission cases and the older cases are behavior-identical → impact: Stop

Simplicity check: considered (a) mirroring the exclusion into the SNAPSHOT to avoid hashing runtime churn — rejected: it does not fix the wedge (the wedge is a CHECK-phase violation, not a snapshot cost), it would need the SAME discriminator to avoid dropping host-curated runtime pre-state (without which the check loses the byte-identical comparison and re-introduces false violations), and it duplicates the discriminator for a pure perf gain; (b) gating on git-status `!!` like tree-pin — rejected: it fails a test fixture that lacks the blanket `*` gitignore (its runtime churn is `??`, not `!!`) and does not express the real intent; (c) INDEX-only discrimination — rejected (host-approved widening): a `git rm`'d or rename-source tracked runtime file is absent from the index but present in HEAD, so index-only would mask a coder deleting host-curated state; (d) PER-PATH ref queries — rejected (host-approved, measured): 139 runtime tokens × 2 queries = 277 subprocesses = 11.6 s per `-Check`. The index-OR-HEAD discriminator loaded as TWO whole-tree inventories ONCE per `-Check` and answered by O(1) set membership (`Test-IsHostCurated`) is exact, scalable, and also eliminates the pathspec-metacharacter hazard (no pathspec matching at all).

### Snapshot-vs-Check determination (host-required)
**The exclusion belongs in the CHECK phase ONLY. The snapshot is left recording everything.** Reasoning, grounded:
- **Check is mandatory.** The wedge is that host runtime churn enters the `-Check` violation set (and, since c1, the written set). Only excluding during attribution removes it. A runtime path dirty ONLY at check-time (`projects/` grows during the dispatch) is in `$nowDirty`, unauthorized, and — without the gate — classified as a violation at ≈699/≈736; the top-of-loop gate skips it first.
- **Snapshot-only would be wrong.** If the snapshot dropped runtime paths but the check did not, a runtime path dirty only-now would be in `$nowDirty`, absent from `$preDirty`/`$preState`, unauthorized → flagged as a fresh violation. So the check gate is required regardless of what the snapshot does.
- **The GONE case confirms check-only suffices.** A runtime path dirty at snapshot then GONE now lives in `$preDirty` (not `$nowDirty`); it enters the loop via the `$allPaths` union (≈645-647) and, without the gate, trips the GONE classification (≈678/≈716, `$wasDirty -and -not $isDirty`) and would be reported GONE — a false alarm on host churn. The top-of-loop gate excludes it first. The discriminator still resolves for a now-absent file because both queries read REFS, not the working file: an untracked-and-deleted runtime path is in neither the index nor HEAD → not host-curated → excluded. Conversely a COMMITTED runtime file the coder `git rm`s is gone from the worktree AND index but still in HEAD → host-curated → stays flagged.
- **Snapshot MUST keep recording host-curated runtime paths.** A host-curated runtime file that is already host-dirty at snapshot and byte-identical since must be recognized as `$untouched` (≈690/≈727) via its `$preState`. If the snapshot excluded it, the check would lack the pre-state and misclassify a host-untouched curated file as a violation. Since the snapshot must record host-curated runtime paths anyway, and the check gate handles non-curated ones over the union, adding a snapshot-side exclusion buys only avoided hashing of churn — a perf gain that duplicates the discriminator and is explicitly out of scope. Snapshot hashing of collapsed ignored dirs is pre-existing, in-process (not a git-subprocess-per-file, per ≈235-266), and folds unreadable subtrees into the hash rather than crashing — an accepted, unchanged cost.

## Specialist Context
### Security
The exclusion is a deliberate, bounded MASK and is documented as loud, not silent: a per-run count of excluded paths is printed so a human reading the log knows non-curated runtime paths were dropped from attribution. The mask is narrowed three ways — (1) root-scoped (only when the worktree IS the runtime root), (2) ref-gated (a path in the index OR HEAD is host-curated state and stays fully checked, including a committed file a coder deletes or renames), (3) dir-list-scoped (only the nine runtime entries). The residual — a coder's brand-NEW file under a runtime dir (in neither ref) — is the host-accepted limit; its defenses are `--sandbox`, the review gate, and the human diff, exactly as the scope check has always stated for a bad-faith coder. `-RuntimeExclusionRoot` IS an override seam: it is a TEST seam mirroring tree-pin.ps1's identically-named parameter — routine dispatch omits it and inherits the default runtime root, so the seam is inert in production. A caller passing it to point the exclusion at an arbitrary tree is out-of-threat-model: this gate defends against a CARELESS coder, not a hostile one deliberately reconfiguring the host's own tooling (the same careless-vs-hostile line the whole script draws). The host records this seam and the accepted new-untracked-file limit in `harness-known-limits.md` at wave close.

### Performance
The discriminator is EXACTLY TWO git subprocesses per `-Check` (one `ls-files -z`, one `ls-tree -r HEAD -z`), loaded once and answered by O(1) HashSet lookups — replacing the rejected per-path design the checker measured at 277 subprocesses / 11.6 s on the live tree (139 runtime tokens). The two inventory calls run only when `$applyRuntimeExclusions` is true — exactly two when it is, zero otherwise. BOTH are ALWAYS loaded when exclusion is active; there is NO first-non-empty short-circuit. Skipping the HEAD (`ls-tree`) inventory when the index (`ls-files`) inventory is non-empty is FORBIDDEN: a `git rm`'d or rename-SOURCE runtime file is absent from the index but present in HEAD, so an index-only read would misclassify it as non-curated and MASK a coder deleting or renaming host-curated state — the exact staged-delete / rename-source protection the HEAD half exists to provide. The snapshot is deliberately unchanged; its hashing of collapsed ignored dirs is pre-existing and in-process. PS 5.1: any new file write (none introduced here beyond c1's existing `-WrittenPathsFile`) must stay BOM-free via `[System.Text.UTF8Encoding]::new($false)`.
