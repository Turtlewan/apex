# Spec: Git path decoding
<!-- Governing contract: ~/.claude/skills/apex-code/references/spec-contract.md. -->

**Identity:** Decode Git path records as strict UTF-8 NUL records in the scope and tree-pin gates.

## Intent
- **Intent:** Make both dispatch safety gates resolve the actual file for every Git path record under either `core.quotepath` setting.
- **Invariants:** Git launch, exit, and UTF-8 decoding failures fail closed for the path-list and status reads that determine scope verdicts and tree-pin fingerprints; the existing deliberate catch-and-continue paths at `codex-scope-check.ps1:987-1006` (inventory/AGENTS fetch failure disables the declared-output class with a warning) and `tree-pin.ps1:326-338` (unreadable-file tolerance) stay unchanged and out of scope. The `# BEGIN build-outputs lockstep` through `# END build-outputs lockstep` blocks in `codex-scope-check.ps1`, `tree-pin.ps1`, and `apex-engine.ps1` remain byte-identical to the current code; every ordinal-comparison, decoding, and parsing change applies only outside those blocks. Distinct Unicode path names remain distinct in path-keyed collections and path comparisons outside those blocks while Windows case-insensitivity is preserved. Legacy line-mode handling of CRLF, lone CR, and LF is preserved. Scope sets and tree-pin fingerprint lines and digests remain byte-identical for ASCII trees whose paths need no Git quoting (no space, `"`, `\`, or control character) and have no glob-collision lookups; existing PATH-injected Git failures still trigger. Fingerprints for trees with space-named paths may change once.
- **Non-goals:** Other Git-output parsers, drain-runner fixture simplification, and skill prose or version changes.

## Assumptions
- Build and tests run under Windows PowerShell 5.1 with Git for Windows. -> impact: Stop
- No dispatch or Engine run spans the upgrade. -> impact: Caution
- Windows forbids double quote and backslash characters in file names; fixtures use a space and square brackets instead. -> impact: Low
- `-Authorized` comma-splits entries, trims whitespace and quotes, then calls `Normalize` (`codex-scope-check.ps1:803-807`). A file name with leading or trailing whitespace cannot be authorized precisely and fails closed; callers rely on the current input parsing. -> impact: Low
- Declared-output pattern matching inside the `build-outputs lockstep` block keeps its current comparison semantics, so an invisible-character variant of a declared build-output path may still match that declaration; changing this requires a coordinated three-file lockstep change in a later spec. -> impact: Low

- A PATH-resolved `.cmd`/`.bat` shim requires the explicit `cmd.exe /d /v:off /s /c` quoted transport specified in Tasks 1 and 2; a resolved `.exe` uses direct CommandLineToArgvW transport. The shim command line permits one `%` for `--format=%cI` and refuses two or more `%` characters before launch. -> impact: Low

Simplicity check: use each script's existing `Invoke-Git` seam, with no shared helper file; UTF-8 decoding and NUL records remove the path-quoting dependency.
