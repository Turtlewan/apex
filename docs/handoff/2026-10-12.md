- Gotcha found only by the full native fence: the new `ProcessStartInfo` Git launchers did not redirect stdin. Inside a `Start-Job`, host git inherited the job's remoting stdin pipe and `git status -z` hung forever. The dispatch-preflight held-dispatch capacity cases stalled for 2h, twice. This was earlier blamed on the Codex sandbox, but it reproduces natively. Fix `cr2`: `RedirectStandardInput` plus an immediate `StandardInput.Close()` in both launchers, with bounded `Start-Job` regression cases in scope-check-test and tree-pin-test. Standing rule: any `ProcessStartInfo` git launcher must redirect and close stdin.
