## Gotchas found (git can't show these)
- **Long dispatches must be HOST-owned via `run_in_background`.** W3's `xhigh` edit to the 1500-line
  wrapper exceeded the 10-min foreground tool ceiling; the Sonnet orchestrator's foreground dispatch
  then left an *alive but orphaned* Codex process the ended subagent couldn't collect. The
  foreground-in-subagent orchestration pattern only works when per-task work fits under ~10 min
  (W1/W2 did; W3 didn't). For big-file/xhigh waves: host launches `run_in_background`, arms a watcher.
- **`-Authorized` needs PowerShell array syntax** `@('a','b',...)`, NOT space-separated bare tokens —
  space-separated spills the 2nd path into the next positional param (`NoOutputTimeoutMin`, int) →
  binding error before launch.
- **Worktree-copy integration leaves no ledger row keyed to the real tree**, so `apex-family-gate`
  can't vouch (would exit 13) even though cross-family review happened. Host is reviewer-of-record.
- **Pre-existing test debt, empirically confirmed (red against the OLD wrapper too):**
  `dispatch-deadlock-test`, `dispatch-encoding-utf8-test`, and the `-SkipScopeCheck`-alone cases were
  already broken before round 8 — fixtures dispatch a workspace-write build with `-SkipScopeCheck`
  alone, hitting the long-standing empty-scope refusal. NOT W3 regressions. Catalogued in the findings
  doc for a small cleanup spec (the two suites W3 didn't otherwise touch remain red).
- **`context-cap-guard` used a synchronous `fs.readFileSync(0)`** — no JS timer can fire during a sync
  read, so it couldn't fail-closed on a held-open stdin (the external 5s hook timeout SIGTERMs it →
  empty stdout → allow). Fixed to the async pattern the other guards use.
