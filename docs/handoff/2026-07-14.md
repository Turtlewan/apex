# Handoff — 2026-07-14

APEX was cut from 50 skills / 17,716 lines to **14 skills / ~2,300 lines**, from 3 operating modes to
**1**, and then live-tested against Artemis. Everything is committed. What follows is only what git
cannot reconstruct.

---

## Decisions Made

**Everything removed today was DeepSeek-era scaffolding that outlived DeepSeek.** Four separate
discoveries, one root cause — this is the thread to hold onto:

1. **ADR-036 — the 36 domain skills.** Rails for a coder that couldn't be trusted to know OWASP or
   bcrypt cost. Codex knows it cold. RED probes reproduced them wholesale.
2. **The keyword registry.** A router for a model that wouldn't self-select skills. Claude Code does
   it natively from `description` frontmatter.
3. **ADR-038 — the mode split.** `ANTHROPIC_BASE_URL` is *session-level*, so reaching DeepSeek meant
   **restarting**. The coder was physically unreachable from a planning session — that, and only
   that, is why planning and coding were separate. **Codex is a subprocess.** The constraint
   evaporated months ago and the entire apparatus (flag, launchers, hook branches, write-guard) kept
   standing.
4. **The 33 `gsd-*` agents.** 14.5 KB of always-on description weight, 4× APEX's own.

**ADR-037 — three context files, hook-enforced.** `CLAUDE.md` (≤200 lines) / `AGENTS.md` (<32 KiB —
Codex *silently truncates* past it) / `status.md` (≤100 lines, **rewritten never appended**).
Decisive fact: **Codex never reads status.md.** So `AGENTS.md` is the Verification Recipe's only
home; a recipe anywhere else is invisible to the coder that runs it.

**Spec ONE WAVE ahead, never the whole roadmap** (now apex-plan's default). Evidence: Artemis's
35-spec one-shot shipped, but **four of six host-caught defects were spec-ahead damage**, and every
one landed in a *chained* family while independent specs came through clean. A spec consuming another
spec's output shape is written against an interface that doesn't exist yet. Interleaving used to cost
a session restart; ADR-038 removed that.

## Specialist Flags — the pattern that runs through every real bug today

**A thing that looks like a control but enforces nothing.** Five instances, all live:

- The **destructive-command guard was disarmed** by ADR-038 — it was gated on a mode that no longer
  existed. `rm -rf` was unblocked for ~3 hours. Found by accident, chasing unrelated dead code.
  **Deleting a mode silently disarms everything conditioned on it.** Check that first, every time.
- **Five declared hard blocks were never enforced** (`git merge`, `branch -d/-D`, SQL drop/truncate).
  The SQL pattern *existed* — but was only tested against `stripQuotedStrings()` output, and
  `splitCommandSegments()` strips quotes *before* segmenting. Every SQL client passes its statement
  as a quoted argument, so **the guard never saw a single one.**
- **`apex-context-budget` — the skill whose job is finding context bloat — was explicitly forbidden
  from pruning it** ("co-installed third-party systems are not APEX's to prune"). It measured the
  14.5 KB, flagged it, and stood down. That rule is why the residue survived every audit.
- **`apex-skill-author` — which owns the Iron Law — had never had the Iron Law applied to it.** A
  bare agent reproduced its entire contents cold, including two of the user's own memories
  (`baseline-test-isolation`, `removal-over-prohibition`).
- **I made the same mistake myself:** I *documented* `codex-scope-check.ps1` as a step for the host to
  remember instead of *wiring it in*. The first real build promptly dispatched without it.
  **Mechanism beats instruction — including when you are the one writing the instruction.**

## Blocked Actions

- **The auto-mode classifier blocked removal of the PreToolUse write-guard** (self-modification). It
  was right to. Needed the user to leave auto mode and approve directly. Expect this for any
  `settings.json` edit that weakens a gate.
- **The destructive guard blocks its own commit messages** when they quote a dangerous command
  (it scans the whole command string, heredoc included). Use `git commit -F <file>`. Narrow, and
  preferable to loosening the pattern.

## What's Next (discoveries)

**The Artemis run is the proving run, and it is only half done.**

`cap-deps-1a` **landed** — `done_with_concerns`, 6 files exactly matching its authorized set, all
gates green. **It is uncommitted in `~/artemis`, awaiting owner review.**

Four dispatch bugs were found *from* that one run and are all fixed + tested:

1. **stdin.** Codex needs the prompt *on* stdin; backgrounding wants stdin *closed* — so a reflexive
   `< /dev/null` clobbers the pipe ("No prompt provided via stdin"). A bare-arg prompt hangs instead.
   `codex-dispatch.ps1` is now the **only** dispatch path; the raw `printf | codex exec` is banned.
2. **The completion report is the LAST `agent_message`, never any other.** `--output-schema` forces
   *every* message into the completion shape, so Codex uses it for narration. That run emitted
   **nine**. The first said `status: done, changed_files: []` — a clean no-op success — while it was
   only just starting. Four middle ones said plain `done` with the right six files and **silently
   dropped the concerns.** Read `.final` (what `-o` captures); never regex the log.
3. **A wrong `-Authorized` would have REVERTED the coder's real work** — strictly worse than no check
   at all, and one quoting slip away. Guard: a task that did real work always touches ≥1 authorized
   file; if none, the *list* is wrong, not the coder. Refuse, exit 66.
4. **Re-dispatching onto a dirty tree turns a build into a rubber-stamp.** Codex's own deviation:
   *"the load-bearing test could not be run red… no result was fabricated."* The earlier dispatch
   **wasn't a clean failure — it wrote the files.** The scope check now warns when an authorized file
   is already dirty.

**The uncomfortable part of #4:** you only know because Codex *volunteered* "no result was
fabricated." A less honest coder says `done`, the tests pass, and you ship an unverified TDD claim.
**That was a courtesy received, not a control held.** The warning is now the actual mechanism.

### Still unproven — pick these up on resume

- **No build has yet gone *through* `codex-dispatch.ps1`.** Both Artemis runs used the raw path (the
  running agent had the old `apex-code` loaded — **a skill edit does not retroactively change a
  running agent**). The scope check, ledger, watchdog and `-Adopt` are all untested in anger.
- **The readiness gate's `Batch-joinable` check has never fired.** It is aimed squarely at the
  `mcp6c` defect (`dto.ts`/`gateway.ts` in *no* spec's file list — would have broken every
  invoke-confirm call at the IPC layer). The next multi-spec plan tests it.
- **Do the trimmed review gates still catch what the domain skills did?** If a spec review misses
  something a domain rulebook would have caught, that is the signal ADR-036 cut too deep — and it is
  one `git revert` away.
