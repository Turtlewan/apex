## Decisions Made

- **Settings.json edit (approved):** Added the destructive-command-guard hook as a second Bash-matcher PreToolUse entry alongside the existing `gsd-validate-commit.sh`. Guard fires on every Bash call in DeepSeek sessions.
- **Hook location:** `~/.claude/hooks/destructive-command-guard.js` (not `scripts/hooks/` — confirmed `~/.claude/hooks/` is the correct directory).
- **Detection scope:** Lifted ECC gateguard's detection functions verbatim (MIT) — `isDestructiveBash`, `isDestructiveGit`, `isDestructiveRm`, `splitCommandSegments`, `stripQuotedStrings`, `explodeSubshells`, `commandBasename`, `findGitSubcommand`, `isReadOnlyGitIntrospection`. Extended with push-to-main refspec detection (new) and `--no-verify` commit flag (not in gateguard).
- **State/speed-bump discarded:** No `markChecked`/`isChecked` — this is a pure hard-block on every attempt, no retry path. That's the entire point (guards the model least likely to honor prose).
- **No `collectExecutableBodies`:** Dropped dependency on `scripts/lib/shell-substitution.js` from ECC. The simplified `isDestructiveBash` still handles subshells (`$(...)`, backticks) via `explodeSubshells` + `splitCommandSegments`. The loss is deep cross-syntax recursion (`$(...)` inside `(...)`) — extremely rare, no test case covers it. If a real-world edge case surfaces, re-add by inlining those extractors.
- **Push-to-main refspec logic:** Added to `isDestructiveGit`'s push handler. Checks each non-flag token as a refspec — if its destination (after `:`) resolves to `main` or `master`, it's denied. Does NOT apply to `--force-with-lease` force detection (that's handled separately).
- **Quote stripping confirmed working:** `DELETE FROM users` inside a `psql -c "..."` is correctly allowed (quoted string, not bare SQL). Bare `DELETE FROM users` is correctly denied.
